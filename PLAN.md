# Booktify — план приложения

**Одной фразой:** настольная программа для Windows, в которую кидаешь книгу на английском
(EPUB, FB2 или PDF) и через некоторое время забираешь готовый EPUB на русском — с сохранённой
структурой, обложкой и глоссарием, который не даёт модели разъезжаться в именах и терминах.

**Для кого:** для одного человека — тебя. Поэтому интерфейс без жаргона: три экрана, крупные
кнопки, все подписи по-русски, никаких «configure endpoint» и «temperature».

---

## 0. Как это выглядит для пользователя

1. Открыл программу. Большое окно, посередине пунктирная рамка: **«Перетащи сюда книгу»**.
2. Кинул файл. Появилась карточка: обложка, название, автор, число глав и слов, примерное
   время и примерная стоимость. Две кнопки: **«Перевести»** и **«Настроить»** (мелкая).
3. Нажал «Перевести». Кольцо прогресса, под ним: «Глава 7 из 24 · осталось ~35 минут».
   Можно поставить на паузу и закрыть программу — при следующем запуске продолжит с того же места.
4. Готово. **«Открыть книгу»**, **«Показать в папке»**, **«Ещё одну»**. Перевод лежит рядом
   с исходником, имя вида `Название (RU).epub`.

Между шагами 2 и 3 — необязательный экран **«Имена и термины»**: таблица, где модель уже
предложила, как писать героев и термины. Можно согласиться со всем одной кнопкой или поправить
пару строк. Дальше эти решения не меняются до конца книги.

## 1. Границы проекта

### Входит в первую версию

- Импорт: **EPUB**, **FB2** (+ `fb2.zip`), **PDF с текстовым слоем**.
- Перевод EN → RU через API: OpenAI-совместимый эндпоинт (DeepSeek, OpenRouter, OpenAI,
  локальный LM Studio/Ollama) + отдельный адаптер под Anthropic-формат.
- Глоссарий: автоматическая заготовка, ручная правка, принудительное соблюдение, проверка после перевода.
- Два прохода качества: черновой перевод и литературная редактура (можно выключить).
- Сборка валидного EPUB 3: обложка, титул, оглавление, сноски, картинки.
- Возобновление после падения, кэш, счётчик денег, лимит расходов.
- Русский интерфейс, работа без установленного Python (один `.exe` + установщик).

### Сознательно не входит

- **OCR сканированных PDF.** Это отдельный тяжёлый модуль (Tesseract/Paddle, +100–200 МБ,
  качество распознавания художественного текста так себе). В v1 сканы честно определяются
  и отклоняются с понятным сообщением. OCR — кандидат на v2.
- **Сохранение вёрстки PDF** (колонки, позиционирование картинок). Из PDF собирается чистый
  EPUB, а не факсимиле.
- Встроенный редактор перевода (правка готового текста в приложении) — v1.1.
- Аудиокниги, синхронизация, мобильные версии, Mac/Linux-сборки (код кросс-платформенный,
  но собираем и тестируем под Windows).
- Собственный биллинг и прокси: ключ твой, запросы идут напрямую с твоей машины.

### Юридическая оговорка

Приложение — инструмент. В «О программе» одна строка: переводить стоит только книги, на которые
у тебя есть право, или для личного пользования. Никаких встроенных библиотек и обменом переводами
приложение не занимается.

                                   │  сигналы Qt, никакой бизнес-логики

│  (epub/fb2/pdf)  model      (блоки)    (LLM+кэш)     (метрики) (epub) │

Ядро не знает про Qt и запускается из консоли (`bt translate book.epub`). Это даёт три вещи:
его можно тестировать без интерфейса, им можно пользоваться по-человечески из терминала,
и GUI можно переписать, не трогая логику.

### Стек и почему именно он

| Слой | Выбор | Почему |
|---|---|---|
| Язык | Python 3.12 | Весь прошлый опыт и парсеры уже на нём; лучшие библиотеки для EPUB/PDF |
| GUI | PySide6 (Qt 6, LGPL) | Настоящее окно, нативный вид, drag&drop, трей; собирается PyInstaller'ом в один установщик |
| Разбор EPUB | lxml + zipfile | Полный контроль над XHTML, сохранение инлайн-разметки |
| Разбор FB2 | lxml | FB2 — это XML, сложностей нет |
| Разбор PDF | PyMuPDF (fitz) | Лучший из бесплатных по скорости и качеству текстового слоя |
| HTTP | httpx | Таймауты, ретраи, HTTP/2, стриминг — без SDK-зависимости от версии API |
| Хранилище задач | SQLite (stdlib) | Возобновление, история, статистика; ничего ставить не надо |
| Ключ API | keyring → Windows Credential Manager | Ключ не лежит в конфиге открытым текстом |
| Сборка | PyInstaller + Inno Setup | Один `.exe`, установщик, ярлык, без Python у пользователя |

Альтернатива, которую я не предлагаю: Electron/Tauri. Красивее, но всю работу с книгами всё равно
придётся писать на Python и держать рядом второй процесс — лишний слой сложности ради внешнего вида.

## 4. Конвейер перевода

Восемь шагов, каждый — отдельный модуль с тестами.

### 4.1 Импорт

**EPUB.** Читаем `container.xml` → OPF → spine. Для каждого документа — XHTML как дерево.
Сохраняем: метаданные (title, author, language, identifier), обложку, CSS, картинки, TOC (`nav`
и/или `toc.ncx`), сноски (`epub:type="noteref"`), инлайн-разметку (`em`, `i`, `b`, `strong`, `a`).
Ничего не «нормализуем» — чем меньше трогаем, тем целее книга.

**FB2.** `description/title-info` → метаданные, `body/section` → дерево глав,
`epigraph`, `poem/stanza/v`, `cite`, `subtitle`, `image` (через `binary`), `notes` → сноски.
FB2-специфику (стихи, эпиграфы) переносим в семантические блоки, а не в кашу из абзацев.

**PDF.** Три эвристики, которые решают 90 % качества:
1. **Определение скана.** Меньше ~100 символов на страницу → «это скан, я так не умею» с
   предложением найти EPUB/FB2.
2. **Основной кегль.** Самый частый размер шрифта = тело текста; крупнее/жирнее = заголовки.
   Колонтитулы и номера страниц отсекаются по повторяемости на одной высоте.
3. **Склейка абзацев.** Переносы с дефисом — склеить; разрыв строки без точки — пробел;
   пустая строка или отступ первой строки — новый абзац. Главы — по закладкам PDF,
   иначе по самым крупным заголовкам.

Все три импортёра отдают одну и ту же **модель документа**, дальше конвейер общий.

### 4.2 Модель документа

```
Book
 ├ meta: title, authors[], language, cover, identifier, source_format
 └ sections[]: {id, kind: chapter|frontmatter|appendix|backmatter, title, blocks[]}

Block
 ├ id: "c07.b012"
 ├ kind: p | h1..h4 | li | blockquote | poem | epigraph | table | image | hr | footnote
 └ html: "<p>He was <em>not</em> amused.</p>"   ← инлайн-разметка остаётся как есть
```

Блок — единица перевода и единица проверки. Именно поэтому потом можно сказать «в главе 7
абзац 12 короче оригинала на 40 %» и показать человеку конкретное место.

### 4.3 Профиль книги

Один дешёвый запрос по первым ~1 500 словам + случайным фрагментам. Возвращает JSON:
жанр, от чьего лица, время, тон, обращение к читателю, есть ли диалектная речь, как передавать
меры и деньги. Это подставляется в каждый последующий промпт — модель перестаёт гадать,
«молодёжное это фэнтези или военный мемуар».

### 4.4 Глоссарий: заготовка

См. раздел 6. На выходе — таблица `EN → RU`, которую пользователь видит и при желании правит
до старта.

### 4.5 Нарезка на блоки

- Цель — **1 200–1 500 слов исходника** на запрос (≈2 500–3 000 токенов ответа).
- Границы — по абзацам, с приоритетом разрывов сцены (`***`), смены говорящего, конца главы.
- Абзац не режется никогда. Слишком длинный абзац (>1 500 слов) режется по предложениям
  с пометкой «продолжение».
- В каждый запрос добавляется **хвост контекста**: последние 2 абзаца исходника и их перевод.
  Без этого модель теряет, кто такой «he» на стыке.
- После главы — короткое резюме (3–5 предложений) в «библию книги», оно идёт в следующие главы.

### 4.6 Перевод

Запрос → JSON `{blocks: [{id, ru}], new_terms: [...], uncertain: [...]}`. Валидация сразу:
все id на месте, количество блоков совпадает, теги сбалансированы. Не сошлось — один ретрай
с обратной связью («в блоке b012 потерян тег `</em>`»), потом — в очередь на ручную проверку,
но конвейер не встаёт.

Температура 0,4 (для «Максимума» — 0,3), top_p 0,95. Ниже — деревянно, выше — начинает
дописывать от себя.

### 4.7 Авторедактура (второй проход)

Берём исходник и черновик, показываем модели как редактору (промпт собран из `RULES.md`):
«найди искажения смысла, потери, кальки, сбои модальности». Ответ — список точечных правок
`{id, find, replace, severity, reason}`, где `find` — точная цитата не короче 40 символов,
встречающаяся в блоке ровно один раз. Применяем только то, что нашлось дословно; остальное
в лог, а не «примерно туда».

Почему это важно: в прошлой книге первый проход дал 532 правки на 183 000 слов, из них
81 критическая. Один проход без редактуры — это книга с ошибкой каждые полторы страницы.
Второй проход стоит ещё ~40 % денег и убирает большую часть.

Третий, необязательный проход — «контрольный» (`VERIFY_RULES.md`): проверить, не испортила ли
редактура то, что было хорошо. В прошлый раз он откатил 40 боковых замен из 532.

### 4.8 QA

Автоматические проверки по каждому блоку и главе — раздел 7. Результат: оценка главы и список
мест, куда стоит посмотреть. Не «идеально/не идеально», а «глава 13: три места с подозрением
на потерю, вот они».

### 4.9 Сборка EPUB

Раздел 8.

### 4.10 Отчёт

Рядом с книгой — `Название (RU).report.md`: модель, режим, время, токены, стоимость, статистика
по главам, все сработавшие проверки, открытые вопросы (`uncertain`). Это то, что в прошлый раз
называлось `EDITOR_REPORT.md`, только автоматически.

## 5. Промпты

Четыре промпта, каждый версионируется (`v1`, `v2`…), версия попадает в ключ кэша — поменял
промпт, старый кэш не подмешивается.

| Промпт | Когда | Примерно токенов |
|---|---|---|
| `profile` + `glossary` | один раз на книгу | 6 000 вход, 2 000 выход |
| `translate` | на каждый блок | 3 000 вход, 2 700 выход |
| `review` | на каждый блок (режим «Стандарт»+) | 5 500 вход, 800 выход |
| `verify` | на книгу, выборочно (режим «Максимум») | 4 000 вход, 600 выход |

Черновики всех четырёх — в `prompts/`. Они собраны из двух источников: того, что сработало
на прошлой книге, и списка её болячек.

### Анти-паттерны, которые промпт закрывает явно

Из `EDITOR_REPORT.md` и `patterns.md`, по частоте:

1. **Снятие модальности.** `could / would / might / seem / likely / almost / still / some`
   превращаются в утверждение. Это главная болезнь прошлого перевода — почти все перевёрнутые
   отрицания отсюда.
2. **Калька управления и порядка слов.** «сделать предложение», «держите глаза широко открытыми»,
   «для меня это был плохой момент влезать в дуэль», постпозиция «лишь».
3. **Причастия → придаточные с «который».** Фраза длиннее и канцелярнее оригинала.
4. **Потеря служебной лексики.** `still`, `some`, `почти`, `прямо`, `как минимум` выпадают
   при склейке предложений.
5. **Сглаживание голосов.** Просторечие, выговор, сухость, сарказм становятся нейтральным текстом.
6. **Плывущая абзацная сетка.** Ремарки отрываются от реплик, внутренний монолог склеивается
   с соседним абзацем.
7. **Канцелярит у подростка-рассказчика.** «появилась лёгкая хмурость» вместо «нахмурился».
8. **Ложные друзья.** «адекватный», «экстравагантный», «академический», «реализовать».
9. **Терминологический дрейф.** Один термин — три перевода; лечится не промптом, а глоссарием
   и проверкой (раздел 6–7).

В системный промпт это входит не списком запретов, а парой «плохо → хорошо» на каждый пункт:
модели гораздо лучше реагируют на пример, чем на правило.

### Формат ответа перевода

```json
{
  "blocks": [{"id": "c07.b012", "ru": "Он был <em>не</em> в восторге."}],
  "new_terms": [{"en": "Current", "ru": "Поток", "type": "term", "gender": "m", "note": "мана-канал"}],
  "uncertain": ["c07.b014: возможно, игра слов на 'charge'"]
}
```

JSON, а не свободный текст, по трём причинам: блоки не перепутаются местами, обрыв ответа
виден сразу (не все id пришли), а `new_terms` и `uncertain` не надо выковыривать из прозы.

## 6. Глоссарий

Требование «чтобы не было путаницы в именах и терминах» — это не одна фича, а четыре.

### 6.1 Заготовка до перевода

1. **Механика.** Вытаскиваем из книги все слова с заглавной буквы, которые встречаются ≥ 2 раз
   и не стоят в начале предложения; плюс устойчивые словосочетания из заглавных; плюс термины
   в кавычках и курсиве. Отсекаем обычные английские имена-слова.
2. **Модель.** Отдаём список с контекстом (по одному предложению на термин): «кто это, как
   передать по-русски, какого рода, склоняется ли».
3. **Слияние.** Дубликаты по исходнику схлопываем, конфликты подсвечиваем.
4. **Экран «Имена и термины».** Таблица: оригинал / по-русски / тип / род / где встретился.
   Кнопки: «Принять всё», «Править», «Добавить». Для 10-летнего — подсказка в одну строку:
   «Так герои будут называться в книге. Можно поменять».

### 6.2 Соблюдение во время перевода

- В запрос попадают **только релевантные** записи: те, что встречаются в этом фрагменте,
  плюс 10–15 «ядерных» терминов мира. Не 355 строк на каждый блок — это и дорого, и размывает
  внимание модели.
- Записи с родом и пометкой «не склоняется» — чтобы «Сера» не превращалась в «Серу» там,
  где не надо, а «Керас» склонялся нормально.
- **Запрещённые варианты.** Если пользователь исправил «Менди» на «Целитель», вариант «Менди»
  уходит в чёрный список и попадает в промпт как «так не писать». Это дешевле, чем ловить потом.

### 6.3 Пополнение по ходу

После каждой главы — дешёвый проход: какие новые имена/термины появились, есть ли противоречия
с уже закреплёнными. Новое добавляется автоматически (в статусе «предложено»), конфликт —
в очередь на решение. В конце книги пользователь видит список из 5–10 спорных мест, а не 300.

### 6.4 Проверка после перевода

Для каждого вхождения термина из глоссария в исходнике проверяем, что в соответствующем
русском блоке стоит закреплённый перевод (с учётом морфологии — по основе слова), и что
запрещённых вариантов нет. Плюс кластерный анализ русских имён собственных: если «Кейденс»
и «Кэденс» встретились в разных главах — это ошибка, и мы её покажем.

Именно эта проверка в прошлый раз нашла шесть расхождений внутри самого глоссария
(Mender/Целитель, Seiryu, Soaring Wings, Беннет, Caelford, род Голоса Башни).

## 7. QA: что проверяется автоматически

| Проверка | Порог | Что делаем |
|---|---|---|
| Число блоков | должно совпадать | ретрай, потом в «проблемные» |
| Отношение RU/EN по словам | 0,75–1,00 на блок; 0,78–0,95 на главу | < 0,7 — подозрение на потерю; > 1,05 — на дописку |
| Английский текст в переводе | 0 слов вне имён | показать место |
| Незакрытые/потерянные теги | 0 | ретрай с указанием блока |
| Потерянные маркеры сносок `[[n]]` | 0 | восстановить, если потерян один; иначе ретрай |
| Типографика | нет `"`, `'`, `...`, двойных пробелов | автопочинка |
| «Ё» | последовательно | автопочинка |
| Глоссарий: термин не переведён как закреплено | 0 | показать; в «Стандарте» — автоправка |
| Запрещённые варианты терминов | 0 | автоправка |
| Дубли абзацев и предложений | 0 | удалить повтор, записать в отчёт |
| Одинаковые начала соседних абзацев (признак склейки) | предупреждение | показать |
| Стоимость и токены | в рамках оценки ±30 % | предупредить, если вышли за лимит |

Из этого складывается **оценка главы** (0–100) и общая оценка книги. Не для красоты: по ней
видно, какие 3 главы стоит перечитать глазами, а какие можно не трогать.

## 8. EPUB: как сохраняется книга

Две ветки.

**EPUB на входе — режим «хирургия».** Не пересобираем книгу заново, а идём по её же XHTML
и заменяем текст внутри блоков. Обложка, CSS, шрифты, картинки, сноски, разбивка — остаются
родными, меняется только язык. Это самый надёжный способ не потерять вёрстку: мы физически
не трогаем ничего, кроме текстовых узлов.

**FB2/PDF на входе — режим «сборка».** Генерируем EPUB 3 по шаблону из `tools/build_epub3.py`:
обложка (из исходника, если есть; иначе — сгенерированная плашка с названием), титул,
оглавление, CSS с «ёлочками» и тире, сноски, картинки.

В обоих случаях:
- метаданные: оригинальное название, автор, язык `ru`, `dc:contributor` = «перевод: <модель>»;
- идентификатор `uuid5` от исходного файла — пересборка той же книги даёт тот же id;
- опциональная страница «От переводчика» с моделью, датой и режимом (можно отключить);
- опциональное **приложение с глоссарием** в конце книги (по умолчанию выключено);
- прогон `validate_epub3`-проверок: mimetype первым и без сжатия, container, OPF, все `idref`
  существуют, XHTML парсится, ссылки живые, spine не пустой;
- если на машине есть Java и epubcheck — дополнительно гоняем его, но приложение от него не зависит.

## 9. Движок задач, надёжность, деньги

- **SQLite-база задач** в `%APPDATA%\Booktify\jobs.db`: книга → главы → блоки, статусы,
  попытки, токены, стоимость. Закрыл программу на 70 % — открыл, продолжил.
- **Кэш** по ключу `sha256(модель + версия промпта + версия глоссария + текст блока)`.
  Повторный запуск после сбоя не платит дважды. Кэш чистится кнопкой в настройках.
- **Параллельность** 3–4 запроса. 429/5xx — экспоненциальный backoff (2, 4, 8, 16 с, до 5 попыток),
  таймаут 180 с, «зависший» запрос перезапускается.
- **Отмена и пауза** — флаг в базе, а не убийство процесса: текущие запросы доживают, чтобы
  не терять оплаченные токены.
- **Лимит расходов**: поле «не тратить больше ___ ₽» в настройках. Дошли — стоп с понятным
  сообщением, уже переведённое сохраняется.
- **Счётчик** в прогресс-баре: «потрачено ≈ 0,42 $». Считаем по токенам из ответа API,
  тарифы — из настроек провайдера (пресеты для DeepSeek/OpenAI, можно вписать свои).
- **Уведомление** о готовности: тост Windows + звук (отключаемо).

## 10. Интерфейс

1. **Одно главное действие на экран.** Всё остальное — мелким шрифтом сбоку.

## 14. Приёмка

Приложение считается готовым, когда выполняется всё:

1. **Форматы.** EPUB, FB2 и текстовый PDF на 300+ страниц проходят без падений; скан- PDF
   даёт понятное сообщение, а не мусор.
2. **Качество.** На тестовой книге: RU/EN по главам 0,75–1,0; ноль латиницы вне имён;
   ноль потерянных сносок; глоссарий соблюдён; субъективная оценка первых двух глав —
   «читается как книга», а не «как перевод».
3. **Надёжность.** Убил процесс на 60 % — после запуска продолжил с 60 %, ничего не оплатил дважды.
4. **Файл.** EPUB открывается в Calibre, Thorium и Apple Books; оглавление, обложка, сноски живые;
   `validate_epub3` — ноль ошибок.
5. **Интерфейс.** Человек, который не знает слов «API» и «токен», проходит путь
   «открыл → кинул → получил» без подсказок.
6. **Цена.** Фактическая стоимость отличается от предсказанной не больше чем на 30 %.
