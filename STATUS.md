# Статус разработки

## Сейчас: Booktify 1.0.0 — релиз готов

Приложение работает целиком: от файла до готового EPUB, с окном и командной строкой.
Собраны две версии:

- `release\Booktify-1.0.0-setup.exe` — установщик с ярлыками и записью в
  «Установка и удаление программ»;
- `release\Booktify-1.0.0-portable-win64.zip` — распаковал и запустил, без установки.

Репозиторий подготовлен к публикации: README, LICENSE (MIT), CHANGELOG, `.gitignore`
и GitHub Actions, который собирает обе версии на тег `v*`.

### Где лежат данные

Настройки, ключ и кэш переводов теперь **не** лежат внутри `dist\Booktify`:
PyInstaller стирает этот каталог при каждой сборке. Порядок выбора:

1. `%APPDATA%\Booktify`
2. `%LOCALAPPDATA%\Booktify`
3. `%USERPROFILE%\Booktify`
4. `dist\Booktify-data` (рядом с папкой программы, переживает пересборку)
5. `dist\Booktify\userdata` — только если данные остались от старых версий;
   при первом запуске переносятся в выбранное место
6. `%TEMP%\Booktify`

Сборка (`build.ps1`) дополнительно сохраняет `userdata` и возвращает его на место
после сборки — на случай, если данные всё ещё там.

### Почему Windows не даёт писать в AppData

Права ACL на папку в порядке (у пользователя полный доступ), Controlled Folder Access
выключена, сторонних антивирусов не найдено. Причина — **уровень целостности процесса**:
в ограниченной среде приложение получает Low IL (`S-1-16-4096`) и не может писать
в `AppData`, `Downloads`, `Документы`, хотя ACL разрешает. Ошибка выглядит как
«Отказано в доступе» (WinError 5).

Приложение теперь пишет уровень целостности в журнал при запуске, показывает
предупреждение в настройках при Low IL и в любом случае выбирает записываемую папку.
В журнал также попадает родительский процесс и его уровень — по этой строке видно,
из проводника запущено приложение или из другого процесса.
«Открыть книгу» и «Показать в папке» в ограниченном режиме не запускают explorer
(он падает с `0xc0000142`), а показывают путь и копируют его в буфер обмена.
Запуск обычным двойным щелчком из проводника даёт Medium IL и штатное поведение.
Подпись кода на уровень целостности не влияет — она убирает только предупреждение
SmartScreen.

### Полировка интерфейса

- **Тёмная тема**: «Как в системе», «Светлая», «Тёмная». В системном режиме
  приложение слушает смену темы Windows и перекрашивается на лету.
- **Недавние книги** свёрнуты в строку со стрелкой и раскрываются плавной
  анимацией (220 мс).
- **Кнопка «Настройки»** — пилюля с шестерёнкой, а не бледная ссылка.
- **Модели**: в настройках подсказка с актуальными именами (`deepseek-flash`
  — это V4.1 Flash, и `deepseek-v4-pro`), имя можно вписать вручную.
- Убран непонятный пункт «Одновременных запросов»: значение осталось внутренним.
- Подзаголовок на главной больше не обещает «через час» — просто «переводим книги
  целиком».

### Исправлено после первого запуска

- **Английский текст в готовой книге**: ответы модели обрезались по лимиту токенов,
  JSON не разбирался, и 12 из 19 фрагментов молча оставались на английском.
  Теперь лимит выхода 16k, целые блоки вытаскиваются даже из обрезанного ответа,
  сбойный фрагмент дробится пополам и переводится частями, а блок без кириллицы
  считается непереведённым и повторяется. Если что-то не вышло совсем — книга
  собирается, но на экране «Готово» появляется предупреждение, а повторный запуск
  докачивает только неудачные блоки.
- **Глоссарий не собирался**: тот же обрыв JSON. Добавлены повтор с коротким
  списком кандидатов и разбор частичного ответа.
- **«Показать в папке» падало** с WinError 5: `os.startfile` на каталоге.
  Теперь проводник открывается через `explorer /select,`, а при неудаче путь
  копируется в буфер обмена и показывается сообщением.
- **Второй этап выглядел как повторный перевод**: кольцо начиналось с нуля, а
  подпись «Вычитываем перевод» затиралась счётчиком. Теперь этапы делят одно
  кольцо (перевод 5–70 %, редактура 70–100 %), подпись этапа и счётчик фрагментов
  показаны отдельно.
- **Сохранение готовой книги**: Windows не дал писать `.tmp` в `Downloads` — перевод
  уже был готов, а файл потерялся на последнем шаге. Теперь приложение проверяет
  папку назначения и при отказе сохраняет книгу в `<папка настроек>\books`,
  сообщая об этом на экране «Готово». Ошибка записи тоже больше не фатальна:
  есть повтор в запасную папку.
- **Папка настроек**: на машине пользователя Windows запрещает создавать
  `%APPDATA%\Booktify` (WinError 5). Приложение теперь проверяет несколько
  мест и берёт первое записываемое: `%APPDATA%` → `%LOCALAPPDATA%` → папка
  `userdata` рядом с программой → `%TEMP%`. Точный путь показан в настройках.
  Если не удалось сохранить даже там, ключ действует до закрытия окна, а приложение
  говорит об этом словами, а не падает.
- **Зависание на «Читаем книгу…»**: исключение при сохранении списка недавних книг
  оставляло окно на экране прогресса без сообщения. Теперь ошибка не фатальна,
  любой сбой показывается диалогом, а всё пишется в `app.log` в папке настроек.
  Плюс сторожевой таймер: если разбор идёт дольше 90 секунд, приложение само скажет.
- **Тёмный выпадающий список**: popup `QComboBox` брал системную тёмную палитру.
  Добавлены стили для `QAbstractItemView`; чекбокс «Показать ключ» заменён на
  текстовую кнопку, поле «Одновременных запросов» — на выпадающий список.
- **Иконка**: добавлена в окно, в панель задач (AppUserModelID) и в сборку
  (`_internal/assets/icon.png`).
- **Длинное название книги** больше не разъезжается: заголовок на экране прогресса
  сокращается и переносится.

### Сборка

```
python -m pip install -r requirements.txt pyinstaller
python -m PyInstaller --noconfirm --clean --distpath dist-next booktify.spec
python -m PyInstaller --noconfirm --clean --distpath dist-setup booktify-installer.spec
```

`dist-next\Booktify` — portable-каталог, `dist-setup\BooktifySetup.exe` — установщик.
Готовые артефакты и контрольные суммы лежат в `release\`.
Иконки рисуются кодом: `python tools/make_icon.py`.

Проверка собранного кода без окна:

```
dist-next\Booktify\Booktify.exe --selftest report.json
```

Отчёт `report.json` показывает, что внутри сборки нашлись промпты, PySide6, lxml,
что книга разбирается, переводится и собирается в валидный EPUB.

### Проверено

- **129 тестов**, все зелёные, включая сквозной прогон «книга → кнопка → фоновый
  перевод → готовый файл» через интерфейс и отдельные тесты на обрезанный JSON,
  дробление фрагментов и отбраковку английского текста.
- **Первый живой прогон** (DeepSeek, книга «Shadows for Silence in the Forests of Hell»,
  18 848 слов): перевод и редактура прошли без ошибок API за 18,5 минуты, все
  фрагменты легли в кэш. Упало только сохранение в `Downloads` — исправлено.
- **Сборка `.exe`**: PyInstaller 6.22 собрал папку 77 МБ; внутри лежат промпты,
  PySide6, lxml, Pillow. Самопроверка `--selftest` внутри сборки: промпт `translate v1`
  загружается, книга разбирается, переводится и собирается в валидный EPUB (2 995 байт).
- **PDF на настоящем файле**: сгенерированная книга с тремя главами, колонтитулами
  и номерами страниц разбирается в 3 раздела по 3 абзаца; колонтитулы и номера
  отброшены, главы распознаны, перевод и сборка EPUB проходят валидацию.
  Скан- PDF отклоняется с понятным сообщением.
- **Оглавление EPUB переводится**: подписи в `nav.xhtml` и `toc.ncx` берутся
  из переведённых заголовков глав. На реальной книге после демо-прогона:
  «ПЕРЕВОД: Глава I — Вход», дальше — исходные, потому что переведены не все главы.
- **Глоссарий собирает модель**: перед переводом она выписывает имена и термины,
  выбирает написание и держит его всю книгу. Пользователю ничего заполнять не нужно —
  ручной экран «Имена и термины» убран.
- **Импорт**: EPUB (XPath для правки на месте), FB2, PDF с текстовым слоем; скан
  определяется и отклоняется.
- **Перевод и редактура**: параллельные фрагменты, кэш, повтор при нехватке блоков,
  точечные правки с проверкой уникальности и разметки.

### Что уже есть

- Импорт EPUB / FB2 / PDF, нарезка с хвостом контекста, глоссарий (markdown/JSON,
  поиск по границе слова, запрещённые варианты, извлечение кандидатов).
- Перевод, редактура, автопроверки (блоки, теги, объём, латиница, типографика, термины).
- Сборка EPUB: пересборка для FB2/PDF и «правка на месте» для EPUB + оглавление.
- Окно: четыре экрана, два диалога, прогресс, отмена, настройки, недавние книги.
- Ключ шифруется Windows DPAPI; в конфиге только шифротекст.
- Подготовка упаковки: spec, build.ps1, иконка, requirements, start.cmd.

### Известные ограничения

- **Окно собранной версии не запускалось**: в моём окружении GUI-процессы не стартуют
  вообще (проверено на пробном 20-строчном `.exe`). Код внутри сборки проверен
  через `--selftest`, но сам факт открытия окна должен подтвердить человек.
- **Реальный API не проверен**: нет ключа. Клиент покрыт тестами на подменённом
  транспорте, но живой ответ провайдера не видели.
- **Окно в исходниках проверено offscreen-рендером**, не живым запуском на мониторе.
- **PDF** проверен на сгенерированной книге, но не на живом издательском файле:
  там бывают колонки, сноски внизу страницы и буквицы.
- **Демо-режим** оставляет английский текст с пометками — это ожидаемо, но
  проверки качества на нём шумят (латиница в каждом блоке).
